# zipdir

`zipdir` は、Git の `.gitignore` に似た直感的なルール定義に加えて、階層的スコープカスケード、スマートな救出・リマップ・リネーム（階層死守・亡命ルート・パス再配置）、および不要ディレクトリの先行枝刈り最適化を備えたディレクトリ・パッケージングツールです。

## 1. インストール・導入

`zipdir` は Python 3.12 以上で動作します。`uv` を用いたグローバルインストールまたはスタンドアロン実行を推奨しています。

### 1.1. uv tool によるインストール (推奨)

ターミナル全体で `zipdir` コマンドを常時利用可能にする場合は、以下のコマンドを実行します。

```sh
# GitHub リポジトリから直接インストール
uv tool install git+https://github.com/IY-del/zipdir.git

# ローカルクローンからインストール
uv tool install ./script/zipdir
```

### 1.2. インストールなしでの即時実行 (uvx)

ツールの事前インストールを行わず、都度実行したい場合は `uvx` を利用します。

```sh
uvx --from git+https://github.com/IY-del/zipdir.git zipdir [options]
```

### 1.3. pipx / pip によるインストール

```sh
# pipx による隔離環境インストール
pipx install git+https://github.com/IY-del/zipdir.git

# 通常の pip インストール
pip install git+https://github.com/IY-del/zipdir.git
```

### 1.4. dotfiles (シェル設定) での運用例

`~/.zshrc` や `~/.bashrc` にエイリアスやラッパー関数を定義することで、プロジェクト内の仮想環境を介して透過的に呼び出すことも可能です。

```sh
# 実行ラッパー例
alias zipd='zipdir'
```

## 2. ユースケース

### 2.1. 大学の課題・レポート提出（LaTeX / Typst プロジェクト）

- **課題**:
  - LaTeX や Typst で執筆したレポートを ZIP で提出したいが、`out/` ディレクトリ内にある大量の中間ファイル（`.aux`, `.log`, `.fls`）や `.git` フォルダは含めたくない。
  - 一方で、ビルドされた最終成果物（`out/report.pdf`）だけはアーカイブに含める必要がある。

  という状況を想定します。
- **解決策**:
  - `clean` を継承した `report` プリセット（[標準プリセット]を参照）を使用します。

    ```sh
    zipdir report -p report
    ```

  - `out/` をまるごと除外しつつ、`!out/*.pdf`（亡命ルート）の働きによって `report.pdf` のみが自動的にアーカイブ直下へリフトされて収録されます。中間ゴミのない綺麗な提出用 ZIP が 1 コマンドで完成します。

### 2.2. ソースコードの提出・配布（クリーンアーカイブ）

- **課題**:
  - プロジェクトを共同作業者や提出先に送る際、容量を食う `node_modules/` や Python の `.venv`、`__pycache__`、秘密情報を含む `.env`、OS 特有のメタデータ（`.DS_Store`、`Thumbs.db`）が混入するのを防ぎたい。
- **解決策**:
  - デフォルトの `clean` プリセットをそのまま実行します。

    ```sh
    zipdir my_project
    ```

  - VCS、エディタ設定、各種キャッシュ、環境変数ファイル、`.zipignore` 自身が自動的に一括除外され、安全かつ軽量な配布 ZIP が生成されます。

### 2.3. サブプロジェクトごとの局所ルール管理とプリセット継承（モノレポ構成）

- **課題**:
  - リポジトリ内に複数のモジュールやサブディレクトリ（`client/`, `server/`, `report/`）が存在し、それぞれ異なるビルド成果物やテスト用ダミーファイルがある。
  - ルート直下の単一設定ファイルだけで全階層の除外・救出パターンを記述しようとすると、ルールが長大かつ複雑になってしまう。
- **解決策**:
  - 各サブディレクトリ直下に個別の `.zipignore` を配置します（詳細は[ルール解決の優先度]を参照）。
    - `client/.zipignore` に `dist/` や `*.map` を記述。
    - `report/.zipignore` に `# inherit: report` や `# include: .gitignore` を記述して、そのサブディレクトリ配下にのみプリセットや局所 ignore ファイルをスコープ適用。

    このように構成することで、Python のローカルスコープ（LEGB 則）のように親から子へ向かって局所スコープが自然にカスケード解決され、ルートを汚さずに各モジュールが自律して除外・継承ルールを管理できます。

### 2.4. 配布用成果物のスマートな配置換え・リネーム（リマッピング）

- **課題**:
  - ビルドによって深い階層（`build/release/bin/app` や `out/report.pdf`）に出力されたファイルを、提出・配布用 ZIP 内では直感的な `dist/` 配下やルート直下に再配置したり、提出指定のファイル名（`final.pdf` 等）にリネームしてパッケージングしたい。
- **解決策**:
  - [構文リファレンス]で定義されているリマップ・リネーム記法を活用します。

    ```md
    dist/!build/release/bin/*
    app!build/release/bin/app
    final.pdf!out/report.pdf
    submitted_*.pdf!out/*.pdf
    /submission.pdf!out/report.pdf
    ```

  - ファイルシステム上の元ディレクトリ構造やビルド成果物の名前を汚すことなく、ZIP 内部での配置先およびファイル名のみを柔軟に制御してアーカイブ化できます。
  - ワイルドカードにマッチした複数ファイルに接頭辞・接尾辞を一括付与したい場合は、ターゲット側に `*` または `$1` プレースホルダ（例: `submitted_*.pdf!out/*.pdf` や `v1_*!dist/*.bin`）を記述することで、複数ファイルが 1 つに集約（メンバー貪食）されることなく、マッチしたファイル名幹（stem）を展開して個別リネーム救出できます。

## 3. 特徴

1. **Python の LEGB 則に倣った 4 階層カスケード解決と全階層継承**
   - 外側から内側、そして実行時引数へと階層的にルールを評価・オーバーライドします。
   - プリセット（Built-in）→ ルート（Global）→ サブディレクトリ（Local）→ コマンド引数（Args）の順に優先度が上がります（[ルール解決の優先度]を参照）。
   - すべての階層の `.zipignore` で `# inherit:` / `# extends:` / `# include:` によるプリセット継承および相対ファイル（`.gitignore` 等）の取り込みが可能です。

1. **3 系統プレフィックスに統一された救出・リマップ・リネーム記法 (`/`・`./`・省略)**
   - ディレクトリ全体を除外した上で、特定の成果物（PDF やドキュメントなど）のみを安全に救出してアーカイブに含めることができます。
   - 出力先オプション `-o` と完全に共通の 3 系統プレフィックスにより、
     - アーカイブのルートを基準とする `/`（`/!`・`/{to}/!`）
     - 元のソース階層や局所スコープを基準とする `./`（`./!`・`./{to}/!`）および `../`（`../!`・`../../{to}/!`）
     - プレフィックス省略により除外され尽くした亡命先（`shallowest_excluded_ancestor.parent`）を基準とする亡命ルート（`!`・`{to}/!`）

     の 3 種類を直感的に記述できます。
   - **救出・リネームの一貫仕様（末尾スラッシュによるディレクトリ／リネーム判定）**:
     - 配置先ディレクトリへの配置には**末尾スラッシュ（`/`）が必須**です（例: `dist/!out/*.pdf`、`/dist/!out/*.pdf`、`./dist/!out/*.pdf`）。
     - 末尾スラッシュがない場合（例: `final.pdf!out/report.pdf`、`app!build/bin`、`dist!out/report.pdf`）は、拡張子の有無に関わらず**ファイルリネーム**として解決されます（拡張子のない実行バイナリのリネームや、異なる拡張子へのリネームも自然にサポート）。
     - 任意の救出ルール `{to}!{pattern}` の先頭に `!` を付与した `!{to}!{pattern}`（例: `!!out/*.pdf`、`!dist/!out/*.pdf`、`!./!out/*.pdf`、`!final.pdf!out/*.pdf`、`!dist!out/*.pdf`）で、該当する救出先やリネーム先のみをピンポイントで打ち消して再除外できます。

1. **非貪欲枝刈り (Non-Greedy Pruning) と 3 段階の貪食 (Phagocytosis)**
   - ディレクトリ走査の前にツリー全体の局所 `.zipignore` を先行探索し、配下に有効な救出ルールがあるディレクトリは誤って除外枝刈り（Prune）されないように保護します。
   - コンパイル時のターゲット認識型ルール圧縮（Squeeze）、実行時の階層的パス評価、およびアーカイブ内の同一パス（`arcname`）衝突時のメンバー置換まで、一貫した貪食（Phagocytosis）モデルで解決します。複数ファイルが同一名にリネーム救出された場合も後勝ちで安全に単一化されます。

1. **3 系統の出力先解決とタイムスタンプ自動フォールバック**
   - デフォルトの出力先はカレントディレクトリ（`./<ディレクトリ名>.zip`）です。ソース内部に出力される場合でも、出力 ZIP 自身は自動的にパッケージ対象から除外されます。
   - `-o` オプションは先頭プレフィックスによって **絶対パス（`/`・`~/`）**、**カレント相対パス（`./`・`../`）**、**ソース親相対パス（`___` または値省略 `-o`）** の 3 系統を直感的に切り替えられます。
   - 出力ファイル名を `.zip` まで明示していない場合（未指定やディレクトリ指定時）、同名の `.zip` が既に存在すると自動的に `-t`（`<stem>_<YYYYMMDD_HHMMSS>.zip`）へフォールバックして完了します。

## 4. 構文リファレンス

ルールは各行に記述し、`#` で始まる行はコメントとして無視されます。

| 記法 | 種別 | 説明 |
| :--- | :--- | :--- |
| `out/` | 除外 (EXCLUDE) | `out` ディレクトリおよびその配下をすべて除外 |
| `*.log` | 除外 (EXCLUDE) | 拡張子が `.log` のファイルをすべて除外 |
| `!out/*.pdf` | 亡命救出 (RESCUE, 省略) | `out` は除外するが、配下の PDF を亡命先（除外され尽くした親階層）へリフトして救出 |
| `dist/!out/*.pdf` | 亡命先相対ディレクトリリマップ | 亡命先（除外され尽くした親階層）を基準として `dist/` 配下へ救出・配置（末尾 `/` 必須） |
| `final.pdf!out/report.pdf` | 亡命先ファイルリネーム | 亡命先を基準としてファイル名を `final.pdf` に変更して救出（末尾 `/` なしはリネーム扱い） |
| `submitted_*.pdf!out/*.pdf` | 動的テンプレートリネーム | ターゲットに `*` または `$1` を含め、マッチした幹を展開して個別リネーム救出 |
| `app!build/release/bin` | 亡命先ファイルリネーム (拡張子なし) | 拡張子のない実行バイナリ等のファイル名を `app` に変更して救出 |
| `dist/final.pdf!out/*.pdf` | ディレクトリ配置 + リネーム | 亡命先の `dist/` ディレクトリ配下に `final.pdf` としてリネーム配置 |
| `./!out/*.pdf` | 階層死守 (RESCUE, `./`) | `out` は除外するが、`out/` 配下の階層構造を完全に維持したまま PDF を救出 |
| `./dist/!out/*.pdf` | ソース階層・スコープ相対配置 | 元のソース階層（サブディレクトリ `.zipignore` 内ではその階層）の `dist/` 配下へ救出・配置 |
| `../!sub/doc.txt` | 親階層リフト (`..`) | `..` の段数分だけ親ディレクトリへ遡って配置（`../../bundle/!` 等の複合指定も可） |
| `/dist/!out/*.pdf` | ルート絶対リマップ | アーカイブの全体ルートを基準として `dist/` 配下へ救出・配置 |
| `/final.pdf!out/report.pdf` | ルート絶対リネーム | アーカイブの全体ルート直下に `final.pdf` としてリネーム配置 |
| `!!out/*.pdf` | 亡命救出打消 (REDELETE) | 先行する `!out/*.pdf`（亡命ルート）による救出を打ち消して再除外 |
| `!dist/!out/*.pdf` | 救出先指定打消 (REDELETE) | 先行する `dist/!out/*.pdf` による救出設定のみをピンポイントで打ち消して再除外 |
| `!final.pdf!out/report.pdf` | リネーム指定打消 (REDELETE) | 先行する `final.pdf!out/report.pdf` によるリネーム救出のみをピンポイントで打ち消して再除外 |

## 5. ルール解決の優先度 (4 階層カスケード)

複数のルール間で競合が発生した場合、以下の優先度に従って解決されます（同一スコープ内では後に定義されたルールが優先されます）。

1. **プリセット (Tier 1: Built-in)**
   - `presets/` ディレクトリに定義された共有ルール。
   - デフォルトで `clean` プリセットが読み込まれます。

1. **ルート `.zipignore` (Tier 2: Global)**
   - アーカイブ対象ディレクトリ直下の `.zipignore`。
   - プロジェクト全体の大域ルールとして適用されます。

1. **サブディレクトリ `.zipignore` (Tier 3: Local / Enclosing)**
   - サブディレクトリ内に配置された局所ルール。
   - 階層が深いサブディレクトリのルールほど、より浅い親ディレクトリのルールを局所的に上書きします。

1. **コマンドライン引数 (Tier 4: CLI Overrides)**
   - `-r` / `--rule`（または `-x` / `--exclude`）など、CLI 実行時に渡された最優先オプション。

## 6. プリセット機能

プリセットファイル（`*.zipignore`）を定義することで、よく使う除外・救出パターンをテンプレート化できます。

### 6.1. 標準プリセット

- **`clean`**:
  - OS メタデータ（`.DS_Store`、`Thumbs.db` 等）、バージョン管理（`.git`、`.svn` 等）、エディタ設定（`.vscode`、`.idea` 等）、Python/Node キャッシュ（`__pycache__`、`node_modules` 等）、環境変数・シークレット（`.env` 等）、および `.zipignore` 自身を除外します。
- **`report`**:
  - `clean` を継承し、`out/` を除外した上で、ビルドされた `out/*.pdf` をアーカイブ直下に亡命リフトして収録します。

### 6.2. プリセットと相対 ignore ファイルの多重継承 (C3 線形化)

プリセットファイルや任意の階層の `.zipignore` 冒頭に `# inherit: <親プリセット名または相対パス>`（`# extends:` / `# include:` も同義）を記述することで、既存プリセットや同一ディレクトリ内の `.gitignore` 等をそのスコープへ多重継承・拡張できます。
ダイヤモンド継承などの多重継承グラフは Python の MRO と同じ **C3 線形化アルゴリズム** によって基底から派生へと一意に順序付けられるため、共通の親プリセット（`clean` 等）が後から重複適用されて派生側の救出ルールを潰してしまう問題を自動的に防ぎます。

```md
# inherit: clean, .gitignore
# description: Custom distribution preset
build/
dist/!build/*.tar.gz
```

## 7. 使い方

### 7.1. 基本的なコマンド

```sh
# カレントディレクトリを ./<dir>.zip にアーカイブ（既存時は _<timestamp>.zip へ自動フォールバック）
zipdir

# ソースの親ディレクトリ (<source.parent>/<dir>.zip) に出力
zipdir -o

# カレント相対パス (./___) で出力先を指定
zipdir -o ./dist/
zipdir -o ./custom.zip

# ソースの親相対パス (___) で出力先を指定
zipdir path/to/my_project -o sibling.zip

# 絶対パスで出力先を指定
zipdir path/to/my_project -o /tmp/custom.zip

# 既存ファイルを上書き (.zip 明示時や同名上書き時)
zipdir -f

# プリセットを指定
zipdir -p report

# プリセット一覧とルール内容を表示
zipdir --list-presets

# 実際に ZIP を生成せず、収録予定メンバーとリマップを確認
zipdir --dry-run

# 個別ルールの追加指定（除外・リマップ・リネーム）
zipdir -r '*.bak' -r 'dist/!*.csv' -r 'final.pdf!out/report.pdf'
```

### 7.2. CLI オプション一覧

- `-o, --output [path]`: 出力先を指定（省略時: カレント `./`、値なしの `-o`: ソースの親、`./___`: カレント相対、`___`: ソース親相対、`/___`・`~/___`: 絶対パス）
- `-t, --timestamp`: 出力ファイル名にタイムスタンプ（`_YYYYMMDD_HHMMSS`）を付与（既定: `False`、未指定・ディレクトリ指定時の重複時は自動フォールバック）
- `-p, --preset <name|path>`: 使用するプリセット名または `.zipignore` ファイルパスを指定（既定: `clean`）
- `--list-presets`: 利用可能なプリセット一覧を表示して終了
- `-r, --rule, -x, --exclude <rule>`: 追加のルール（除外・救出・再除外・動的リネーム）を指定（複数指定可、`-r` / `--rule` 推奨）
- `--no-default-rules`: プリセットのルールを一切適用しない
- `--name <name>`: アーカイブのルートディレクトリ名および既定のプレフィックスを指定
- `--flat`: ZIP 内部に最上位の親ディレクトリを含めず、直下に展開されるようにフラット化
- `--compression <0..9>`: 圧縮レベルを指定（0: 無圧縮、1〜9: デフレート、既定: 6）
- `-f, --force`: 同名ファイルが存在する場合に上書き
- `-v, --verbose`: 救出・除外されたファイルの詳細情報を表示
- `--dry-run`: アーカイブを作成せず、結果のプレビューのみを表示
