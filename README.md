# zipdir

`zipdir` は、Git の `.gitignore` に似た直感的なルール定義で不要な中間ゴミを一括除外しながら、ビルド成果物（`out/report.pdf` や `dist/`）だけをスマートに救出・配置・リネームできるディレクトリ・パッケージングツールです。

「`zip -r` を叩いたら `.git` や `node_modules/`、`.DS_Store` まで巻き込まれてしまった」「ビルド中間生成物（`.aux` や `.log`）は捨てたいが、生成された PDF だけは ZIP 直下に含めたい」といった課題を、1 コマンドで解決します。

```text
【一般的な zip コマンド】                 【zipdir コマンド】
project/                               project.zip
├── .git/          ── 混入! ──> 含まれる    ├── src/
├── node_modules/  ── 巨大! ──> 含まれる    ├── README.md
├── out/                               └── report.pdf  <── out/ から救出・配置!
│   ├── report.aux ── ゴミ! ──> 含まれる
│   └── report.pdf ── 成果物 ──> 含まれる
├── src/
└── README.md
```

## 1. クイックスタート

### 1.1. インストールなしでの即時実行 (uvx)

Python 3.12 以上と `uv` があれば、事前インストールなしで即座に実行できます。

```sh
uvx --from git+https://github.com/iotaish/zipdir.git zipdir [options]
```

### 1.2. グローバルインストール (uv tool)

ターミナル全体で `zipdir` コマンドを常時利用可能にする場合は、以下を実行します。

```sh
uv tool install git+https://github.com/iotaish/zipdir.git
```

### 1.3. 最もシンプルな実行

引数なしで実行すると、カレントディレクトリを対象に不要ゴミを自動除外した `<ディレクトリ名>.zip` を生成します。

```sh
zipdir
```

- デフォルトで組み込みの `clean` プリセットが働き、`.git/`, `node_modules/`, `__pycache__/`, `.venv/`, `.DS_Store`, `.env` などを自動で一括除外します。
- 生成された ZIP ファイル自身がパッケージ内に紛れ込むことも自動で防止されます。

## 2. 代表的な活用レシピ

### 2.1. レポート・論文の提出 (LaTeX / Typst)

- **目的**: ビルド中間ゴミ（`.aux`, `.log`, `.fls` 等）を排除し、生成された `out/report.pdf` だけをアーカイブ直下に救出して提出用 ZIP を作成する。
- **コマンド**:

  ```sh
  zipdir -p report
  ```

- **解説**: `report` プリセットは `out/` をまるごと除外した上で、`!out/*.pdf` によって PDF のみを自動的にアーカイブ直下へ引き上げて収録します。

### 2.2. 配布用ソースコードのクリーン ZIP化

- **目的**: 共同作業者や顧客、課題提出先へソースコード一式を送る際、巨大なライブラリや秘密情報、OS メタデータを除去する。
- **コマンド**:

  ```sh
  zipdir path/to/project -o ./submission.zip
  ```

- **解説**: VCS リポジトリ、エディタ設定、仮想環境、環境変数ファイルが除外された清潔な `submission.zip` が作成されます。

### 2.3. 提出先指定のファイル名への自動リネーム

- **目的**: 成果物名（`out/report.pdf`）を、提出指示で指定された学籍番号付きの名称（`2026_thesis.pdf`）に変えて収録する。
- **コマンド**:

  ```sh
  zipdir -p report -r '2026_thesis.pdf!out/report.pdf'
  ```

- **動的リネーム（複数ファイルの一括展開）**:
  ターゲット側に `*` または `$1` を含めることで、元のファイル幹（stem）を活かした動的リネームも可能です。

  ```sh
  zipdir -r 'submitted_*.pdf!out/*.pdf'
  ```

  `out/chap1.pdf` → `submitted_chap1.pdf`、`out/chap2.pdf` → `submitted_chap2.pdf` として個別に救出されます。

### 2.4. ファイル容量超過や空アーカイブの防止ガード

- **目的**: 大学の提出システム（Manaba / Moodle 等）やメール添付のサイズ上限（例: 10MB）の超過事故や、除外ルールミスによる空 ZIP の生成を防止する。
- **コマンド**:

  ```sh
  zipdir -p report --max-size 10MB --check-empty --strict-rescue
  ```

- **ガード内容**:
  - `--max-size 10MB`: 圧縮後のサイズが 10MB を超過した場合、エラーで終了し未完全な ZIP を安全に自動削除（ロールバック）します。
  - `--check-empty`: アーカイブ内のファイル数が 0 件の場合にエラー終了します。
  - `--strict-rescue`: 指定した救出ルール（`!out/*.pdf` 等）が 1 件もマッチしなかった場合に警告終了し、ビルド失敗のまま提出してしまう事故を防ぎます。

### 2.5. 複数パターンのブレース一括指定

- **目的**: カンマ区切りのブレース展開で、複数拡張子やディレクトリを 1 行で直感的に指定する。
- **コマンド**:

  ```sh
  # jpg, png, webp を一括除外
  zipdir -r '*.{jpg,png,webp}'

  # client または server 配下の .py を除外
  zipdir -r 'src/{client,server}/**/*.py'

  # 数字範囲やオプショナルサフィックスの併用
  zipdir -r 'file.{[0-9],bak}' -r 'data{,[0-9]}.csv'
  ```

### 2.6. ルール評価の診断・デバッグ (--explain)

- **目的**: 「なぜこのファイルが除外されたのか」「どのルールで救出されたのか」をステップ順に追跡する。
- **コマンド**:

  ```sh
  zipdir --explain out/report.pdf
  ```

- **出力例**: 各階層でのマッチ状況（`EXCLUDE` → `RESCUE` 等）と、最終的なアーカイブ内配置パス（`arc_path`）が色付きで分かりやすく表示されます。

## 3. ルール記法リファレンス

ルールは各行に記述し、`#` で始まる行はコメントとして無視されます。
プロジェクト直下の `.zipignore` やコマンドラインの `-r` オプションで指定可能です。

### 3.1. 基本ルール（除外・救出・再除外）

| 記法 | 種別 | 説明 |
| :--- | :--- | :--- |
| `out/` | 除外 (EXCLUDE) | `out` ディレクトリおよびその配下をすべて除外 |
| `*.log` | 除外 (EXCLUDE) | 拡張子が `.log` のファイルをすべて除外 |
| `!out/*.pdf` | 救出 (RESCUE) | `out/` 全体は除外するが、配下の PDF だけを引き上げて救出 |
| `!!out/draft.pdf` | 再除外 (REDELETE) | 先行する `!out/*.pdf` による救出を打ち消して再度除外 |

### 3.2. 救出先の 3 系統プレフィックス（配置・リネーム）

救出ルール `{to}!{pattern}` では、ターゲット側の末尾スラッシュの有無で**ディレクトリ配置**と**ファイルリネーム**を直感的に使い分けることができます。

- **末尾スラッシュあり (`/`)**: ディレクトリ配下へ配置
- **末尾スラッシュなし**: その名前へリネーム

| プレフィックス記法 | 配置基準 (アンカー) | 記述例と動作 |
| :--- | :--- | :--- |
| **プレフィックス省略** | 亡命ルート（除外された親階層） | `dist/!out/*.pdf` → `out` の親階層にある `dist/` 配下へ救出<br>`final.pdf!out/report.pdf` → 親階層に `final.pdf` としてリネーム救出 |
| **ルート絶対 (`/`)** | アーカイブ全体のルート直下 | `/dist/!out/*.pdf` → アーカイブ直下の `dist/` 配下に配置<br>`/final.pdf!out/report.pdf` → アーカイブ直下に `final.pdf` として配置 |
| **階層死守・相対 (`./`・`../`)** | 元のファイル階層や局所スコープ | `./!out/*.pdf` → `out/` の階層構造を完全に維持したまま救出<br>`../!sub/doc.txt` → 1 階層上の親ディレクトリへリフト |

> **打消し記法**: 先頭に `!` を付けた `!dist/!out/*.pdf` や `!final.pdf!out/report.pdf` で、特定の救出・リネーム設定のみをピンポイントで打ち消して再除外できます。

### 3.3. パターンマッチ拡張（ブレース・POSIX 文字クラス）

本家 Git の `.gitignore` にはないブレース展開や、`.gitignore` と完全な互換性を持つ標準 POSIX 文字クラスをサポートしています。

| 記法 | 構文機能 | マッチ例 |
| :--- | :--- | :--- |
| `*.{jpg,png,webp}` | ブレース展開 (OR) | `photo.jpg`, `logo.png`, `hero.webp` にマッチ |
| `file.{[0-9],bak}` | ブレース内ブラケット | `file.1`, `file.9`, `file.bak` にマッチ |
| `file{,[0-9]}.txt` | オプショナル選択肢 | `file.txt`, `file1.txt` にマッチ |
| `*[[:blank:]]*` | 空白・タブ文字クラス | スペースやタブを含むファイル名にマッチ（生のタブ入力を回避） |
| `*[[:punct:]]*` | 記号文字クラス | 記号全般を含むファイル名にマッチ（エスケープ地獄を回避） |
| `*.[^0-9]` | キャレット反転 | 数字以外の 1 文字にマッチ（※`!` は救出予約のため `^` を推奨） |

> **Git 互換性について**:
> `.gitignore` との互換性確保のため、POSIX 標準の 12 文字クラス（`[:digit:]`, `[:alnum:]`, `[:alpha:]`, `[:blank:]`, `[:punct:]`, `[:space:]`, `[:xdigit:]` 等）をすべて内部で解釈可能です。日常の記述では打鍵しやすく直感的な `[0-9]` や `[a-z]` の利用を推奨します。

## 4. 出力先の柔軟な指定 (-o オプション)

`-o` / `--output` オプションは、指定するプレフィックスに応じて直感的に出力先を決定します。

```sh
# 1. カレントディレクトリ相対 (./ または ../)
zipdir -o ./dist/           # ./dist/<name>.zip に出力
zipdir -o ./custom.zip      # カレント直下の custom.zip として出力

# 2. 値なしの -o または ソース親相対 (プレフィックスなし)
zipdir -o                   # <source.parent>/<name>.zip に出力
zipdir -o backup.zip        # <source.parent>/backup.zip に出力

# 3. 絶対パス (/ または ~/)
zipdir -o /tmp/archive.zip  # /tmp 配下に直接出力
```

- **タイムスタンプ自動フォールバック**:
  出力先を `.zip` まで明示していない場合、同名のアーカイブが既に存在すると自動的に `<name>_<YYYYMMDD_HHMMSS>.zip` へ退避して保存します（`-f` で強制上書きも可能）。

## 5. ルール解決の優先度 (4 階層カスケード)

複数のルール間で競合が発生した場合、Python の変数スコープ（LEGB 則）のように、外側から内側、そしてコマンドライン引数の順にオーバーライドされます。

```text
Tier 1: 共有プリセット (Built-in)
   ↓  (ルート設定で上書き)
Tier 2: ルート .zipignore (Global)
   ↓  (サブディレクトリ設定で局所上書き)
Tier 3: サブディレクトリ .zipignore (Local)
   ↓  (実行時引数で最優先上書き)
Tier 4: コマンドライン引数 -r / --rule (CLI Overrides)
```

- **非貪欲枝刈り (Non-Greedy Pruning)**:
  配下に有効な救出ルール（`!out/*.pdf` など）が存在するディレクトリは、誤って早期除外されないよう自動的に探索保護されます。

## 6. プリセット機能とルール共有

### 6.1. 標準プリセット一覧

- **`clean`** (既定):
  OS メタデータ（`.DS_Store`、`Thumbs.db` 等）、VCS（`.git`、`.svn` 等）、エディタ設定（`.vscode`、`.idea` 等）、Python/Node キャッシュ（`__pycache__`、`node_modules` 等）、環境変数・秘密鍵（`.env` 等）、および `.zipignore` 自身を一括除外します。
- **`report`**:
  `clean` を継承し、`out/` ディレクトリを除外した上で、ビルドされた `out/*.pdf` をアーカイブ直下に救出します。

利用可能なプリセットの一覧は `zipdir --list-presets` で確認できます。

### 6.2. プリセット継承と .gitignore の取り込み

`.zipignore` ファイルの先頭に `# inherit:`（または `# extends:`, `# include:`）を記述することで、既存プリセットや既存の `.gitignore` を取り込めます。

```md
# inherit: clean, .gitignore
# description: Custom distribution preset

build/
dist/!build/*.tar.gz
```

- ダイヤモンド継承などの多重継承グラフは、Python と同じ **C3 線形化アルゴリズム** によって矛盾なく順序付けられます。

### 6.3. スタンドアロンルール出力 (--dump-rules / --freeze-rules)

外部プリセットや多階層サブディレクトリを解決した「最終確定ルール」を、単一の自己完結な `.zipignore` として書き出すことができます。

```sh
# 確定した全ルールを標準出力にダンプ（CI や検証向け）
zipdir --dump-rules

# プロジェクト直下の .zipignore に固定出力（スタンドアロン化）
zipdir --freeze-rules
```

- プリセットが存在しない CI 環境や、`zipdir` の設定を持たない第三者にプロジェクトを渡す際でも、全く同一のパッケージング結果を 100% 再現できます。

## 7. CLI オプション一覧

| オプション | 型・既定値 | 説明 |
| :--- | :--- | :--- |
| `directory` | 引数 (既定: `.`) | アーカイブ対象ディレクトリ |
| `output_path` | 引数 (省略可) | 出力先パス（`-o` の位置引数エイリアス） |
| `-o, --output` | パス文字列 | 出力先（`./` カレント、値なし `-o` 親ディレクトリ、`/` 絶対パス） |
| `-p, --preset` | 文字列 (既定: `clean`) | 適用するプリセット名または `.zipignore` パス |
| `--list-presets` | フラグ | 利用可能なプリセット一覧を表示して終了 |
| `-r, --rule` | 文字列 (複数可) | 追加ルール（除外・救出・再除外・リネーム、`-x` も同義） |
| `--no-default-rules` | フラグ | プリセットの既定ルールを一切適用しない |
| `--max-size` | サイズ文字列 | アーカイブの最大許容サイズ（例: `10MB`, `500KB`）。超過時ロールバック |
| `--check-empty` | フラグ | アーカイブ内のファイル数が 0 件の場合にエラー終了 |
| `--strict-rescue` | フラグ | 設定した救出ルールで 1 件も救出されなかった場合にエラー終了 |
| `--dump-rules` | フラグ | 解決・圧縮済みのルール列をスタンドアロン `.zipignore` 形式で stdout 出力 |
| `--freeze-rules` | フラグ | 解決・圧縮済みのルール列を `<source>/.zipignore` に直接保存 |
| `--explain` | パス文字列 | 指定したファイルの評価履歴（除外・救出・リマップ）を診断表示 |
| `--flat` | フラグ | 最上位ディレクトリを含めず、中身のみを直下に展開して ZIP 化 |
| `--name` | 文字列 | アーカイブ内ルートディレクトリ名および既定ファイル名 |
| `-t, --timestamp` | フラグ | 出力ファイル名にタイムスタンプ（`_YYYYMMDD_HHMMSS`）を付与 |
| `-f, --force` | フラグ | 同名ファイルが存在する場合に強制上書き |
| `-v, --verbose` | フラグ | 救出・除外されたファイル詳細を表示 |
| `--dry-run` | フラグ | ZIP を生成せず、収録予定メンバーとリマップ結果のみを表示 |
| `--compression` | 数値 (0..9, 既定: 6) | 圧縮レベル（0: 無圧縮、1..9: デフレート圧縮） |

## 8. インストール・環境設定

### 8.1. uv / uvx による導入 (推奨)

```sh
# 常時インストール
uv tool install git+https://github.com/iotaish/zipdir.git

# ローカルクローンからインストール
uv tool install ./script/zipdir

# 一時実行
uvx --from git+https://github.com/iotaish/zipdir.git zipdir [options]
```

### 8.2. pipx / pip による導入

```sh
pipx install git+https://github.com/iotaish/zipdir.git
pip install git+https://github.com/iotaish/zipdir.git
```

### 8.3. シェルエイリアス運用の推奨

`~/.zshrc` や `~/.bashrc` に短いエイリアスを設定すると日常のパッケージングがさらに快適になります。

```sh
alias zipd='zipdir'
```
